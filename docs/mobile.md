# Mobile editing

Phones default to Web Layout: text reflows to the available width at readable 100% zoom. Print Layout remains available to check pagination and initially fits the page to the screen. Rotating or resizing preserves an explicit view choice. Reflow changes the view, never the document's page settings or print/export layout.

The touch contract is:

- Drag one finger to scroll. Swiping preserves the caret, selection, document, objects and browser text-input focus; it does not reopen the software keyboard.
- Tap to place the caret and focus text input. Tap, then immediately drag from nearby to select text. The second contact must start within 350 ms and 28 screen points of the completed tap; movement beyond 8 points starts selection.
- Use two fingers to pan and pinch to zoom about their midpoint. Adding a finger cancels single-finger selection handling until every finger has lifted.
- Cancellation or lost focus clears gesture state. A canceled gesture cannot become an edit later.

Narrow screens keep the full ribbon, following GridCraft's mobile approach. Swipe the tab strip to browse tabs, then swipe the command groups independently; mouse dragging also scrolls both rows. A toolbar swipe can start over a button or font field without activating it or editing text. Lift after a tap to activate a command. File operations and undo/redo remain at the top, while the status bar offers the Print Layout/Web Layout switch. Search Commands is an optional entry in File.

With a mouse, a plain vertical wheel over either ribbon row pans it sideways: wheel down reveals commands to the right, and wheel up returns to earlier commands. This works on narrow desktop windows too. Horizontal and diagonal gestures retain their direction, including their smoothed tails; the document still scrolls vertically, and Ctrl+wheel over the document still zooms.

Touch input is handled separately from the synthetic mouse events browsers also emit, including eframe's immediate pointer callbacks before the real touch events. The browser adapter captures document pointer callbacks and delivers document contact endings directly to the gesture classifier, bypassing eframe's unconditional canvas/text-input refocusing. Only a confirmed completed document tap requests fresh keyboard activation. Scrolling, canceled contacts and pinching retain the existing focus, including when the keyboard is already open. Ribbon gestures use the existing bounded touch classifier and route horizontal movement through egui's wheel path. Completed toolbar taps process their click release during the browser touch callback, preserving user activation for file dialogs/downloads. Mouse selection in the document and wheel/trackpad behavior retain their existing paths.

Regression tests send timestamped egui touch events with the accompanying browser-style pointer events. They browse every ribbon tab, drag over an enabled Cut button and a font field, then verify that tapping Bold still formats the selection. Wheel tests cover phone/desktop widths, independent ribbon rows, diagonal input, document scrolling and Ctrl+wheel zoom. Document tests compare content and selection before and after navigation, check the exact text replaced by a selection gesture and verify midpoint anchoring and caret visibility. Headless Chromium additionally exercises the built WASM application through touch and wheel events at phone/tablet sizes and compares every exported paragraph against an imported text file. Its DOM event trace rejects blur/refocus cycles during scrolling, cancellation and pinching, and verifies that a completed tap still activates typing; clock-sync markers ensure trace collection has finished before assertions. These checks run in `./test` and Nix CI. Physical iOS/Android keyboard, accessibility and stylus validation require device testing.
